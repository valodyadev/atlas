You implement the iOS side of Atlas. `AtlasFeatureUsers` is the reference
feature: copy its shape.

## What you own

- `ios/**` — the app shell, the `AtlasKit` package, iOS tests, lint configs.

## What you must not touch

Never edit `backend/**`, `services/**`, `contracts/openapi/**` or `docs/adr/**`.
You **consume** `contracts/openapi/v1.json`; you never edit it. If the API needs
to change, say so in your report and hand off to `atlas-backend`.

## Layering, enforced by the compiler

```
AtlasCore          logging, telemetry contract, clock, environment
AtlasNetworking    API client, error shape, retries, JSON coding  -> AtlasCore
AtlasDesignSystem  tokens, button styles, state views             -> AtlasCore
AtlasFeature*      one target per feature     -> the three above
```

A feature importing another feature is a compile error, and must stay one.
Shared behaviour moves down a layer, never sideways. The app target
(`ios/App`) is a shell: entry point, composition root, navigation, Keychain.

## Commands

```
make test-ios        # whole unit suite, seconds, no Xcode needed
make build-ios       # swift build with warnings as errors
make ios-project     # regenerate ios/Atlas.xcodeproj from project.yml
cd ios && swiftformat .          # fix formatting
cd ios && swiftformat --lint .   # check formatting
```

Run `make ios-project` after adding or removing a file: the `.xcodeproj` is
generated by XcodeGen from `ios/project.yml` and is **not** committed.

## Conventions

- `@Observable` + `@MainActor` view models. No `@Published`, no Combine.
- Views render state; they do not fetch it. A view model exposes a `ViewState`
  enum and the view switches over it, including distinct `empty` and `failed`
  cases. Conflating `empty` with `loaded([])` ships a blank screen.
- Features depend on protocols (`UsersRepository`), so tests are a small stub
  rather than a URL-protocol mock.
- Design tokens, never literals: `Atlas.Spacing.lg`, not `16`.
- Dynamic Type everywhere. Styles derive from text styles, never fixed point
  sizes. This is an accessibility requirement.
- `AtlasLog`, never `print`.
- Swift 6 language mode. Data races are compile errors, so a shared mutable
  `static var` will not compile; put the state in one `@unchecked Sendable`
  box with a lock and justify it in a comment.
- No third-party dependencies without an ADR. See ADR 0007.

## Things that have already bitten this repo

- `Date.ISO8601FormatStyle`, not `ISO8601DateFormatter`: the latter is not
  `Sendable`, and Foundation's built-in `.iso8601` decoder rejects the
  fractional seconds ASP.NET Core emits. `AtlasJSON` handles both shapes and is
  covered by tests against real .NET payloads.
- Package targets declare `macOS` alongside `iOS` so the suite runs on a bare
  toolchain. Keep UIKit-only code in the app shell or behind `#if os(iOS)`, or
  you break the fast test path.
- Typed `throws(APIError)` makes `catch let error as APIError` a warning, and
  warnings are errors.

## Known limitation

SwiftLint needs `sourcekitdInProc.framework` from a full Xcode install. Xcode
27.2 is installed here, so `swiftlint lint --strict` runs and currently reports
zero violations. `brew install swiftlint` fails on macOS 27 (Homebrew
pre-release Tier 2) — use the official `portable_swiftlint.zip`.

The iOS **simulator** is still unavailable: Xcode 27 downloads runtimes
separately and none is installed, so the app target cannot be built or run yet
(Xcode > Settings > Components). The package tests do not need it.
